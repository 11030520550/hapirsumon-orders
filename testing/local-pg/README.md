# גרסת ההדגמה המקומית: האתר האמיתי על PostgreSQL אמיתי, עם נתונים פיקטיביים

**מה זה:** האתר עצמו (`index.html`, `app.js`, `business-app.js`, `styles.css`) רץ מול PostgreSQL 18 אמיתי (PGlite) בתוך הדפדפן.

- **בניית המסד:** המסד נבנה מקובצי ה-SQL של הפרויקט, בסדר המתוכנן לייצור:
  schema ← reliability ← business-upgrade ← sheets-and-order-numbers ← orders-v3 ← sheets-v2 ← enforce ← cutover.
  אחר כך מורצים קובצי ה-verify.
- **כללי המסד:** RLS, ההרשאות, ה-cutover וכל פונקציות ה-RPC פועלים כמו ב-Supabase.
- **בלי Supabase ובלי ייצור:** הנתונים נשמרים רק בדפדפן הזה (IndexedDB) ולא יוצאים מהמחשב.
- **סימון:** בתחתית המסך יש פס אדום: "גרסת הדגמה · נתונים פיקטיביים בלבד". הפס הזה קיים רק בגרסה המקומית.

## הפעלה
**צריך:** Node.js וגם Chrome או Edge.

1. לוחצים לחיצה כפולה על `testing\local-pg\start-local.cmd`. אפשר גם להריץ משורש הפרויקט:
   ```
   node testing/local-pg/start-local.mjs
   ```
2. פותחים את **http://127.0.0.1:8010/**. אם הדף נפתח לפני שהשרת עלה, מרעננים.
3. מתחברים:

   | חשבון | סיסמה | מה מאפשר |
   |---|---|---|
   | `staff@local.test` | `test1234` | המשתמש הרגיל ("צוות מזכירות") |
   | `second@local.test` | `test1234` | משתמש שני מאושר ("צוות מכירות") |
   | `pending@local.test` | `test1234` | משתמש שלא אושר, לבדיקת חסימה |

4. **בפעם הראשונה** נבנית גרסת ההדגמה, בתוך כ-15 שניות. אחר כך היא נשמרת בין פתיחות.
5. **עצירה:** Ctrl+C בחלון השרת.

**איפוס:** הכפתור "איפוס הנתונים" בפס האדום בונה את המסד מחדש, למצב ההתחלתי של ההדגמה. הנתונים זהים בכל בנייה.

**מסדים נפרדים:**
- `?db=<שם>` פותח מסד נפרד, למשל `http://127.0.0.1:8010/?db=meeting`.
- `?seed=basic` בונה מסד קטן במקום נתוני ההדגמה. זה הסט שבדיקות הקצה-לקצה רצות עליו, במסד `e2e`.

## מה יש בנתוני ההדגמה
הנתונים נוצרים בהרצה מחדש של כ-16 שבועות פעילות, דרך אותן פונקציות שהמסכים מפעילים. השעון של המסד מוזז לכל פעולה, ולכן לכל שורה יש התאריך שהיה לה במציאות.

**לקוחות וגיליונות:**
- **30 עסקים פיקטיביים.**
- **22 גיליונות, אחד בכל יום ראשון:**
  - 16 גיליונות שפורסמו.
  - הגיליון הנוכחי.
  - גיליונות מתוכננים.
  - גיליון חג שנסגר ידנית.

**הזמנות:**
- כ-110 הזמנות, כספיות ובקרדיטים.
- הזמנות בכל שלבי ההפקה: ממתינות לקובץ, ממתינות לאישור, טרם שובצו, שובצו ופורסמו.
- כמה הזמנות מבוטלות.

**חבילות ותשלומים:**
- **8 חבילות, עם משלמים מסוגים שונים:** בזמן, באיחור, חלקי, ומשלם שהפסיק לשלם.
- **תשלומים:**
  - תשלומים חלקיים.
  - צ'ק שחזר ושולם מחדש.
  - חיובים באיחור, עתידיים, וחיובים ללא מועד פירעון.

**קרדיטים:**
- יתרות חיוביות, אפס ושליליות.
- התאמות ידניות עם סיבה.
- עריכת לוח תשלומים אחרי רכישה.

**נתוני בסיס:**
- **מחירון:** המוצרים והמחירים לקוחים מהמחירון הציבורי (`reference/`). הקרדיטים לכל מודעה הם ערכי הדגמה בלבד, כי העסק עוד לא הגדיר אותם.
- **מונה ההזמנות:** 22354, כמו ביום המעבר מגוגל שיטס. ההזמנות מתחילות ב-22355. **בייצור המונה לא שונה.**

**עקביות:** בכל בנייה נבדק ש:
- **חיובים:** סך החיובים שווה לסכום שהתקבל ועוד היתרה הפתוחה.
- **קרדיטים:** היתרות שוות לסכום התנועות.

את הבדיקה מריצים כך: `node testing/local-pg/seed-check.mjs`

## בדיקות אוטומטיות מקצה לקצה
כשהשרת רץ, מריצים בחלון נוסף:
```
node testing/local-pg/run-e2e.mjs
```

**מה נבדק:**
- **34 תרחישים על המסכים האמיתיים ב-Chrome.** כל תוצאה נבדקת ישירות במסד בשאילתות SQL.
- **תהליך מלא:** לקוח חדש ← חבילה ← הזמנות ← מעבר גיליון ← תשלום ← ביטול.
- **הסכמה בין המסכים:** מסך הבית, הדוחות וקובצי ה-CSV תואמים לנתוני המסד.

**צילומי מסך:**
```
node testing/local-pg/screenshots.mjs <תיקייה>
```

## מגבלות
- **מה מוחלף בגרסה המקומית:**
  - **ההתחברות:** חשבונות מקומיים.
  - **Realtime:** מתעדכן רק משינויים באותו טאב.
  - **PostgREST:** מתורגם בקובץ `pg-supabase.js`.
- **מה נבדק רק בפרויקט הבדיקות:** Auth אמיתי, Realtime בין מחשבים, וביצועים ברשת.
- **בלי CSP:** השרת המקומי לא שולח CSP, כי PGlite צריך WebAssembly. ה-CSP של הייצור נבדק בבדיקות ה-Mock (`testing/browser/`).
